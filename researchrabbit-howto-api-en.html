Introduction

This document explains, from first-hand use of the logged-in app, how to use ResearchRabbit and how to search for information. It also documents the real HTTP endpoints the single-page app calls (host api.researchrabbit.ai), with the actual request/response shapes observed while performing searches, opening articles, and creating collections.

All endpoint details below were captured live from the running app's network requests (fetch/XHR), not from any official public API doc. ResearchRabbit does not publish a public API; these are the private endpoints the SPA uses. Treat them as reference for understanding/automation, not as a stable contract.

Base hosts

  • Web app (SPA): https://app.researchrabbit.ai
  • Backend API: https://api.researchrabbit.ai
  • Auth: cookie/session based (requests use credentials: include). Google OAuth is supported on the login page.

Core concepts

Seed articles

The starting point(s) for a search — a paper you know or pick. The algorithm uses seeds to find connected work.

Search session

A container for one research thread; holds ordered steps. URL: /search/{sessionId}/{stepIndex}.

Search (a step)

A single query run within a session — either a keyword search or a citation-network search.

Edges

Citations (forward) and references (backward). edgeMode: "both" | "forward" | "backward".

Collections

Called folders in the API. Group saved articles with colors; support subcollections.

Project

A workspace scoped by projectId; almost every endpoint requires it.

App layout (after login)

  • Top nav: Search · Library · Upgrade · Test · account menu.
  • Search home: a single box "Title, DOI, or keywords…" + a Search button and Browse Library. Side panels show Recently saved, Library (collections), and What's New.
  • Search results page: left = list of candidate/seed articles; right = article detail panel (Abstract, Author, DOI, "Dive deeper" with Similar / Refs / Cited By counts, plus Collection and Reading List actions).
  • Library page: Collections sidebar (Create Collection), All Articles, import (BibTeX, Zotero), Export, in-library Search, Label.
  • Rabbit Diagnostics: a command palette (Ctrl/Cmd-style) with "Enter command…" — a power-user/dev helper.

How to search — the big picture

ResearchRabbit has two search modes that chain together:

  1. Keyword search (find seeds): type a title, DOI, or keywords → get a flat list of matching articles (e.g. "1–10 of 4,700,000").
  2. Network search (discover via citations): pick one or more seed articles → run a Similar / Refs / Cited By search → get ranked, connected articles (e.g. "1–20 of 376").

Then you iterate: select useful results as new seeds and run another step — "Grow and go!"

1) Keyword search (finding seed articles)

1
On the Search home, type into "Title, DOI, or keywords…" (e.g. climate change adaptation).
2
Click Search. The app navigates to /search/{sessionId}/0 and shows a "Pick where to start" list of candidate articles.
3
Each result shows author/year, title, journal, and abstract. Incomplete-data items are flagged. Footer shows total matches (e.g. "1–10 of 4,700,000").
Tip: Keyword search matches in title and abstract. RR+ adds boolean operators (AND, OR, NOT) and quoted exact phrases, powered by Google Scholar.

Behind the scenes: a POST /searches is sent with a stringFilter and stringFilterTypes: ["title","abstract"] (see Request examples).

2) Network search (discovery via citations)

1
From the keyword list, click an article to select it as a seed. The detail panel opens; the Search button becomes enabled.
2
Click Search (or one of Similar / Refs / Cited By in "Dive deeper").
3
A new step is created (URL /search/{sessionId}/1) showing ranked connected articles, e.g. "Citations of Owen, 2020 — 1–20 of 376".
4
Use the controls More citations / More recently published to re-rank, and References / Search inputs / Results / Next Search to move between steps.

Behind the scenes: POST /searches with type:"singleSet", set.articleIds:[21400232], edgeMode:"both", outputType:"articles", per:20. The response includes results.totalCount (e.g. 1893) and a scored items array.

The three "Dive deeper" directions

  • Similar — all connection types (citations + references + co-citation + co-authorship + semantic). Largest set.
  • Refs (Earlier Work) — the references of the seed (edgeMode: backward).
  • Cited By (Later Work) — articles citing the seed (edgeMode: forward).

Iterating ("Grow and go!")

The prompt "Select articles to help your next search find more accurate results" is the heart of ResearchRabbit. Select one or more results → click Next Search → the app runs a new network search using your selections as seeds, refining results toward your interest. Each iteration is a new step in the session. The page hint literally reads: "Improve your results by selecting articles to add to your search."

There is a cap on seed articles per search: 50 on Free, 300 on RR+. That is why iterating in chunks matters for large reviews.

Library & collections

  • Create Collection: Library → Create Collection → enter a name → Create. (API: POST /folders with name, color, projectId.)
  • Save an article: from any article panel, click Collection (add to a folder) or Reading List (park to read later).
  • Subcollections & multi-collection: a collection can have parent collections (sub-subcollections), and one article can live in multiple collections; notes/edits travel with it.
  • Autosave: optionally auto-file every article used as a seed into a chosen collection.
  • Recently Found: every article touched in a search, grouped by time (API: GET /recent-articles?isSaved=false).
  • All Articles: your saved library (API: GET /user-articles?sortBy=nickname&sortDirection=asc).

Import & export

  • BibTeX: import a .bib file (file input on Library) or export selections as BibTeX.
  • Zotero: connect via OAuth (API: GET /oauth-tokens lists linked tokens) and import your Zotero library; collections map 1:1 to ResearchRabbit folders.
  • Export: export a collection or selection (BibTeX / citation formats) from the Export button.

API endpoints observed

All under https://api.researchrabbit.ai. Auth via session cookies; most calls require projectId as a query param.

MethodEndpointPurpose
GET/users/meCurrent user profile (id, email, name, OAuth/password flags, marketing, ToS acceptance, emailVerifiedAt).
POST/searchesRun a search — keyword (stringFilter) or network (set.articleIds/authorIds + edgeMode). Returns results.items + totalCount.
GET/searches/{id}?projectId=…Fetch a previously created search's results.
POST/search-sessionsCreate a new search session (a research thread).
GET/search-sessions/{id}?projectId=…Get a session, including its ordered steps[].
PATCH/search-sessions/{id}/steps/{stepId}Update a step: set inspectedType/inspectedId (which article is open), searchId (which search the step shows), or selected[].
GET/articles/{id}Full article metadata: title, abstract, authors (with h-index & citation count), DOIs, OpenAlex/Semantic Scholar/arXiv/PubMed IDs, forwardEdgeCount (citations), backwardEdgeCount (references), retracted, doctype, publication date/title.
POST/user-articles/batch?page=1&per=9Check/save articles into the user's library in batch.
GET/user-articles?projectId=…&sortBy=nickname&sortDirection=asc&page=1&per=50List saved articles (library).
GET/recent-articles?projectId=…&isSaved=false&page=1&per=20"Recently Found" — articles touched in searches.
GET/readings?projectId=…&page=0&per=2000Reading List items.
POST/folders?projectId=…&includeItemCounts=true&sortBy=createdAt&sortDirection=ascCreate a collection. Body: {name, color, projectId}.
GET/folders?projectId=…&includeItemCounts=true&…List collections with itemCount, position, color.
GET/oauth-tokensList linked OAuth integrations (e.g. Zotero).
Analytics calls also fire (Mixpanel api-js.mixpanel.com/track, Google Analytics region1.analytics.google.com/g/collect with tid G-XP3TQTP6W7) and event names like new-search-session — these are telemetry, not data endpoints.

Request examples (real bodies captured)

A) Keyword search — POST /searches

{
  "type": "singleSet",
  "projectId": "4e1dd100-1004-498d-88c0-8cb60e48277d",
  "set": {
    "userArticleIds": [], "articleIds": [],
    "authorIds": [], "folderIds": [], "tagIds": []
  },
  "outputType": "articles",
  "showPlaceholders": true,
  "per": 10, "page": 1,
  "stringFilter": "climate change adaptation",
  "stringFilterTypes": ["title", "abstract"]
}

Response (excerpt): results.items[] with score:0, each details having id, title, firstAuthor, authorString, publicationDate, publicationTitle, dois, openAlexIds, forwardEdgeCount, backwardEdgeCount, retracted, doctype, url.

B) Network search (Similar) — POST /searches

{
  "type": "singleSet",
  "projectId": "4e1dd100-1004-498d-88c0-8cb60e48277d",
  "set": {
    "userArticleIds": [],
    "articleIds": [21400232],
    "authorIds": [], "folderIds": [], "tagIds": [],
    "edgeMode": "both"
  },
  "outputType": "articles",
  "showPlaceholders": true,
  "per": 20, "page": 1
}

Server expands seeds (it adds finalArticleIds/finalAuthorIds) and returns results.totalCount (e.g. 1893) and ranked items[] with score (e.g. 5).

For Cited By use edgeMode:"forward"; for Refs use edgeMode:"backward".

C) Inspect an article in a step — PATCH /search-sessions/{id}/steps/{stepId}

{ "inspectedType": "article", "inspectedId": "21400232" }
// or, to point the step at a new search result set:
{ "searchId": "b64ccb7a-229a-4468-a572-c2bccb1a9baa" }

D) Get article detail — GET /articles/21400232

E) Create a collection — POST /folders?projectId=…&includeItemCounts=true

How these endpoints were observed

While logged in, I injected a small fetch/XMLHttpRequest interceptor into the SPA page that recorded method, URL, request body, status, and a snippet of each response to window.__net. I then performed real actions — a keyword search, selecting a seed, running a Similar search and a Cited-By search, opening an article, navigating to the Library, and creating a collection — and read back the recorded calls. The endpoints, bodies, and response shapes in this document come directly from those captured requests.

You can reproduce this in Chrome DevTools: open Network → Fetch/XHR, then click around the app. Filter by api.researchrabbit.ai to see exactly these calls.

Practical usage tips

  • Start broad, then narrow: keyword search → pick 1–3 strong seeds → Similar → select the best → Next Search. Repeat.
  • Use directions: Refs for foundations (what a paper built on), Cited By for follow-ons (what built on it), Similar for the widest net.
  • Mind the seed cap: Free = 50 seeds/search, RR+ = 300. For big reviews, chain steps instead of one giant search.
  • Organize as you go: create collections per topic; use Reading List for "read later"; Autosave to auto-file seeds.
  • Incomplete data on an article means missing metadata — you can still save it and fill in details manually.
  • Signals (RR+): watch for high-risk-article indicators when evaluating credibility.
  • Export early: BibTeX/Zotero export works on collections and selections; pair with Zotero for writing.
  • Don't rely on citation counts alone: Google Scholar counts differ from ResearchRabbit's (different sources/metadata).
