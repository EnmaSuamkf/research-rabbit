Literature discovery by chat

Find the papers that matter — just ask Warren.

Warren is an AI literature-discovery assistant for ResearchRabbit. Tell it your review topic and it finds seed papers, grows the citation frontier (similar / earlier / later work), screens and ranks candidates, checks credibility, and hands you off to ResearchRabbit — every paper it shows you carries a real DOI.

Chat with Warren now Use it in Claude Code

Warren never invents a citation. If a tool returns nothing, it says so. It works off metadata and abstracts only — it will not tell you "this study found X" unless X is in the abstract it was given.

What is this?

A conversational front door to ResearchRabbit's citation graph. Instead of clicking through databases and building a seed set by hand, you have one short conversation and walk away with a ranked, DOI-backed shortlist and a link to keep exploring visually.

🛡️

It never fabricates a citation

Every title, author, year, venue and DOI comes from a tool result in the same turn. No DOI, no recommendation. A fabricated citation is the worst thing it can do — so it won't.

🌱

It grows the frontier

Similar work (the widest net), earlier work (foundations / references), later work (cited-by, optionally since a given year), or a one-call consensus-ranked expansion.

📊

It ranks by consensus

Each candidate carries seedHits (how many of your seeds connect to it) and citationsPerYear (so a strong 2024 paper beats a tired 1998 one).

🔗

It hands off to ResearchRabbit

A ResearchRabbit session link on its own line, tappable on mobile — a real app.researchrabbit.ai/search/… deep link into your account, never a fabricated URL.

From first question to ranked shortlist

Six short turns. Warren asks only what it needs and never makes you repeat yourself.

  1. Frame

    It restates your question in one line and notes the angle you care about — population, outcome, mechanism, equity lens, time window.

  2. Seed

    search_keyword on 1–3 phrasings of the topic. It shows 3–5 candidate seeds, each with DOI + citedBy, and asks you to pick 1–3 (or name a known paper).

  3. Expand

    The direction that matches your question: search_similar, search_earlier_work, search_later_work, or expand_frontier for a broad shortlist in one call.

  4. Screen & rank

    screen_articles drops papers outside a year / doctype / citation floor or retracted ones; rank_candidates orders the shortlist with a reason per item.

  5. Verify

    Before endorsing a paper, credibility_check covers retraction, doctype, venue, counts and first-author h-index — with the caveats folded in.

  6. Hand off

    A ResearchRabbit link on its own line, so you can tap it on your phone and keep going visually in the app.

Architecture

Four moving parts, one request path. An agentflow for the conversation, a language model for the decisions, an MCP server for the tools, and a REST gateway that speaks to the ResearchRabbit API (api.researchrabbit.ai) using your session token.

  • Agent & chat UI

    Flowise 3.1.2

    A Docker service hosting the Agentflow — a Start node into an Agent node. It serves the chat window in the corner of this page and orchestrates every turn.

  • Language model

    Fireworks glm-5p2

    accounts/fireworks/models/glm-5p2 at temperature 0.2, streaming on, with allMessages memory so the whole conversation stays in context. Native tool-calling.

  • Tool layer

    MCP server (22 tools)

    Node + Express with the @modelcontextprotocol/sdk, speaking Streamable HTTP on POST /mcp. Stateless: one JSON-RPC message per request. All 22 tools are wired to the agent.

  • Data layer

    REST gateway → ResearchRabbit

    A Node + Express service in front of the ResearchRabbit API (api.researchrabbit.ai), authenticated with your sessionToken JWT (sent as Authorization: Bearer). It exposes plain REST endpoints the MCP tools call and maps RR's citation graph into a canonical paper shape with real DOIs.

The path of a single question

  1. 1

    You

    "Find me 5 seed papers on urban tree canopy and heat equity, each with a DOI." goes into the chat window.

  2. 2

    Flowise Agentflow

    Flowise receives the message, adds the Warren system prompt and the allMessages history, and hands the turn to the Agent node.

  3. 3

    Fireworks LLM

    The model decides whether it needs data and, if so, which of its 22 MCP tools to call and with what arguments.

  4. 4

    MCP server

    The tool call arrives over Streamable HTTP at POST /mcp and is dispatched to the matching tool implementation.

  5. 5

    REST gateway → ResearchRabbit

    That tool calls the gateway, the only component allowed to talk to api.researchrabbit.ai directly (with your session token). It returns real papers with real DOIs.

  6. ↩

    …and back the same way

    Gateway → MCP server → the model, which turns the raw result into a DOI-backed answer and streams it token by token into the chat window.

All three services — Flowise, the MCP server and the REST gateway — are deployed as Render web services. The agentflow, the MCP endpoint and the prediction endpoint are all public; to get real ResearchRabbit data you connect your account with your sessionToken — via the Connect panel (web) or the X-RR-Token MCP header (editor).

Use the same tools in Claude (and any MCP client)

The 22 tools that power Warren are an MCP server. You don't need Flowise to use them — connect the server straight to Claude Code, Claude Desktop, Cursor, Windsurf or VS Code and you get the same literature-discovery tools inside your editor. They run against the ResearchRabbit API (api.researchrabbit.ai), so you must send your sessionToken JWT as the X-RR-Token header on every request — see Use your own account and Option B below.

The endpoint

Hosted (always on): https://researchrabbit-mcp-server.onrender.com/mcp
Local (when running the repo): http://localhost:8822/mcp

Required — your session token: send one header on every POST /mcp — X-RR-Token (your sessionToken JWT from app.researchrabbit.ai localStorage). The server forwards it to the gateway, which calls api.researchrabbit.ai as you with Authorization: Bearer (and auto-discovers your projectId). Without it the tools cannot reach ResearchRabbit.

Transport: Streamable HTTP, stateless. One JSON-RPC request per POST /mcp. GET /mcp returns 405; the descriptor lives at GET /. No initialize handshake is required — just send tools/list or tools/call.

Option A — Claude Code (one command)

Register the server with the Claude Code CLI. The --transport http flag is the key part — this is an HTTP server, not a stdio subprocess.

terminalbash
# register the hosted MCP server (project scope by default)
claude mcp add --transport http researchrabbit https://researchrabbit-mcp-server.onrender.com/mcp

# or, when running the repo locally:
# claude mcp add --transport http researchrabbit http://localhost:8822/mcp

# verify it connected
claude mcp list
claude mcp get researchrabbit

The CLI registers the server without a header. To use it you must then edit the generated .mcp.json to add the X-RR-Token header shown in Option B (claude mcp add doesn't take headers directly). Or skip the CLI and use Option B from the start.

Option B — project .mcp.json (Claude Code, Cursor, Windsurf, VS Code)

Drop this file at the root of your repo (or your home directory). It is the portable, version-controllable way to share the server with your team — every MCP-aware client reads the same format. The headers block below carries your ResearchRabbit session token (Camino B) — it is required, not optional. See how to get your sessionToken.

.mcp.jsonjson
{
  "mcpServers": {
    "researchrabbit": {
      "url": "https://researchrabbit-mcp-server.onrender.com/mcp",
      "headers": {
        "X-RR-Token": "<your sessionToken JWT>"
      }
    }
  }
}

Option C — Claude Desktop

Add the same server to your Claude Desktop config (claude_desktop_config.json → Developer → Edit Config):

claude_desktop_config.jsonjson
{
  "mcpServers": {
    "researchrabbit": {
      "type": "http",
      "url": "https://researchrabbit-mcp-server.onrender.com/mcp",
      "headers": {
        "X-RR-Token": "<your sessionToken JWT>"
      }
    }
  }
}

Then restart Claude Desktop. After restart, the 🔌 tools icon will list 22 researchrabbit__* tools. Approve them once and Warren's tools are available in the desktop chat too.

Use your ResearchRabbit account

Warren runs on the ResearchRabbit API (api.researchrabbit.ai), so you must connect your account with a sessionToken JWT — it is mandatory. Once connected, Warren uses your data: real searches, sessions, collections, library, and the app.researchrabbit.ai/search/… deep link. There are two ways to connect, one per surface — both end up at the same gateway, which calls ResearchRabbit as you with Authorization: Bearer.

Method B — in your editor (Claude, Cursor, …)

Send your credential as request headers on the MCP server. Each call then uses your RR session, and the credential lives in your local config — never on the server. This is the per-user path. See the exact .mcp.json / claude_desktop_config.json with the headers block in MCP & Claude (Option B / C).

Method C — on this page (web chat)

Use the panel on the right. Paste your sessionToken once; it is stored only on the gateway, for this chat, and every Warren turn then runs against your RR account. Disconnect any time. After about a day (or if the token expires) you reconnect. Your projectId is auto-discovered — you don't need to paste it.

One active web account at a time. The web chat channel keeps a single connected account (the last one you connect). True simultaneous multi-user would need per-request identity from Flowise's MCP node, which it doesn't provide — so the editor path (Method B) is the per-user one; the web panel is the single-account one. For a shared demo team setup, use Method A (one account in gateway env vars) instead.

How to get your sessionToken

ResearchRabbit keeps your signed-in session as a JWT in the app's localStorage. Copying it takes about a minute:

  1. Open app.researchrabbit.ai and sign in (email/password or Google).
  2. Open DevTools (F12) → Application → Local Storage → https://app.researchrabbit.ai. Click the tokens key. The value is JSON like {"sessionToken":"eyJ…"} — copy just the sessionToken string (the long eyJ… JWT, not the whole JSON).
  3. Paste it into the panel above (Method C) or into the X-RR-Token header of your .mcp.json (Method B), and you're connected. Your projectId is auto-discovered — you don't need it.

What is a session token? It's a bearer credential — anyone who has it can act as you on ResearchRabbit. That's why it's stored only on the gateway (not in the chat transcript, not in the repo) and why you should disconnect when you're done. It expires on its own; if Warren says “session expired”, just repeat the steps with a fresh token.

Until then the panel reports “not available on this gateway yet”. The MCP header path (Method B) works as soon as the new mcp-server/ is deployed too.

3. Grow the frontier — expand_frontier

One call that runs N network iterations server-side and returns a deduped, consensus-ranked shortlist — the “Grow and go!” loop in a single tool call.

requestbash
curl -X POST https://researchrabbit-mcp-server.onrender.com/mcp \
  -H 'content-type: application/json' \
  -H 'accept: application/json, text/event-stream' \
  -H 'X-RR-Token: <your sessionToken>' \
  -d '{"jsonrpc":"2.0","id":3,"method":"tools/call",
       "params":{"name":"expand_frontier",
                 "arguments":{"seeds":[
                   "Disproportionate exposure to urban heat island intensity across major US cities",
                   "Trees Grow on Money: Urban Tree Canopy Cover and Environmental Justice"
                 ],"iterations":2,"limit":10}}}'

Each returned item carries seedHits (how many of your seeds connect to it) and citationsPerYear, so you can say “cited by 4 of your 5 seeds” — a reason a human accepts.
